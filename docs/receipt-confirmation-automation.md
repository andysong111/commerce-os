# 입고확정 자동화 안전 계약

## 확정 흐름

```text
중국 발주·입고 관리에서 입고확정
→ 정상입고 수량과 확정 원가·재고원장 저장
→ Ops Center에 receipt.confirmed.v1 이벤트 전달
→ 가격조정 엔진 분석 자동 실행
→ 가격 변경안 생성
→ AWAITING_APPROVAL 상태 저장
→ 사용자가 최종 승인한 경우에만 Shopling 가격 실행
```

## 가격 정책

- 가격 인상은 신규 확정 입고원가가 상승해 `판매가 = 원가 × 2` 기준을 밑돌 때 제안한다.
- 마진 보호가 우선이므로 인상률 상한은 두지 않는다.
- 판매·주문 캐시가 24시간을 넘으면 가격 인하와 단종 정리 판단에 사용하지 않는다.
- 일반 인하와 단종 정리는 1회 최대 5%만 제안한다.
- 가격 인하와 단종 정리는 기본 선택하지 않는다.
- 입고확정 이벤트는 실제 Shopling 가격 실행 API를 호출할 수 없다.

## 실패와 중복 처리

- 모든 입고확정 이벤트는 고유 event ID를 가진다.
- Ops Center는 처리한 event ID를 저장해 재전송 중복을 막는다.
- 중국 발주·입고 관리는 외부 반영 성공 전까지 Outbox 이벤트를 삭제하지 않는다.
- 실패 이벤트는 5분 뒤 재시도하며 앱을 열었을 때도 대기 이벤트를 복구한다.
- 자동화 실행, 실패, 최종 승인 대기와 Shopling 가격 작업 상태변경은 감사로그로 남긴다.

## 데이터 최신도

| 데이터 | 허용 기준 | 오래됐을 때 |
|---|---:|---|
| 확정 입고원가 | 5분 내 연동 | 가격분석 후속 흐름 실패 표시·재시도 |
| 판매·주문 데이터 | 24시간 | 발주안, 인하, 단종 판단 차단 |
| 상품·옵션 연결 | 24시간 | 실제 Shopling 가격 실행 차단 대상으로 표시 |
| 추정재고 | 24시간 | 발주 판단 차단 대상으로 표시 |
| 가격 변경안 | 24시간 | 새 분석 필요 상태로 표시 |

## 배포 순서

1. Ops Center Supabase migration 적용
2. 가격조정 엔진과 상품마스터 배포
3. Ops Center 배포 및 연동 상태 확인
4. 중국 발주·입고 관리 D1 migration 적용
5. 중국 발주·입고 관리 배포
6. 실제 쓰기 없이 상태·캐시·분석 생성까지만 통합 점검
7. 다음 실제 입고확정 건부터 운영 적용

Ops Center 로그인 우회는 이번 변경 범위에서 유지하며 별도 안정화 단계에서 복구한다.
