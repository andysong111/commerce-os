# 빠른 발주안 MVP 운영정책 V2.1

목표는 완벽한 재고확정을 기다리지 않고 **오늘 실제로 볼 수 있는 발주 판단·검토 목록을 최대한 넓게 제공**하는 것이다.

## 1. 완전한 추정재고 밴드가 있을 때

- `ORDER_DIRECTION_STABLE`: 낮은 재고와 높은 재고 양쪽 모두 발주가 필요하면 두 권장수량 중 작은 값만 발주 검토수량으로 사용한다.
- `HOLD_DIRECTION_STABLE`: 양쪽 모두 보류면 오늘 발주하지 않는다.
- `INVENTORY_SENSITIVE`: 재고 가정에 따라 발주/보류가 뒤집히면 수동 검토로 남기고 수량은 0으로 둔다.

## 2. 최신 입고증거만 부족할 때의 빠른 절충

정체성과 과거 누적 발주이력이 증명되어 있고 `cumulativeResidualCandidate`를 만들 수 있으면 다음 임시 계획재고를 사용한다.

`임시 계획재고 = max(0, 과거 누적 발주수량 - 최근 360일 exact Canonical 판매수량)`

이 값은 실제재고가 아니다. 360일 이전 판매가 차감되지 않고 일부 과거 발주가 실제 입고되지 않았을 가능성도 있어 실제보다 높게 계산될 수 있다. 따라서 **과잉발주보다 발주가 늦어질 가능성을 허용하는 상한편향 절충값**으로만 사용한다.

- 기존 발주 엔진의 수요목표·미입고 약정·MOQ·박스입수를 그대로 적용한다.
- 결과가 양수면 `보수적 발주 검토`.
- 결과가 0이면 `보수적 발주 보류`.

## 3. 재고증거가 아직 없는 기존 발주후보

기존 Canonical 발주엔진에서 `발주 추천` 또는 `소량 검토`이고 재고 0 가정 결과가 양수지만 위 두 종류의 재고증거가 없는 상품은 숨기지 않는다.

- `수요만 수동검토`로 표시한다.
- 기존 발주엔진의 `recommendedQty`는 `재고0 수요참고`로만 표시한다.
- 실제 `MVP 주문검토수량`은 **0**으로 유지한다.
- 근거는 `DEMAND_ONLY_ZERO_STOCK_REFERENCE`로 표시한다.
- 위험은 `OVER_ORDER_IF_MISUSED`로 표시한다.
- 사용자가 해당 상품의 재고가 충분하다고 기억하면 바로 보류할 수 있고, 부족하다고 판단할 때만 참고수량보다 작은 범위에서 직접 주문수량을 정한다.

즉 이 단계는 재고를 아는 척하지 않고 **사용자 판단에 필요한 수요 정보만 먼저 공개**하는 절충이다.

## 4. 안전 경계

이 MVP는 Product Master 재고를 VERIFIED로 승격하지 않는다. 중국 주문 Draft, 결제, 자동발주, 재고 write는 하지 않는다. `재고0 수요참고`를 실제 주문수량으로 자동 복사하지 않는다. 실제 품절 시 `SOLD_OUT_RESET=0`, 이후 신규 입고와 판매가 쌓이면서 PROVISIONAL 추정치를 점진적으로 대체한다.
