# 빠른 발주안 실시간 호출 실패 절충정책

빠른 발주안은 실시간 데이터 호출의 일시적 실패 때문에 전체 화면이 막히지 않아야 한다.

- 실시간 V2.2 로드는 최대 2회 시도한다.
- 두 번 모두 실패하면 마지막 정상 운영검증 시점의 42개 발주후보와 재고0 수요참고를 `LAST_KNOWN_MANUAL_FALLBACK`으로 연다.
- 이 fallback에서는 모든 행을 수동검토로 취급하고 시스템 발주/보류 판정은 0건으로 둔다.
- `재고0 수요참고`는 실제 주문수량이 아니며 기존 브라우저 작업대의 참고상한 제한을 그대로 적용한다.
- Product Master 재고승격, 중국 주문/결제, Shopling 변경, purchase/inventory write는 하지 않는다.
- 실시간 데이터가 다시 살아나면 fingerprint가 달라져 fallback에서 입력한 이전 브라우저 계획을 자동 재확인하게 한다.

목표는 완벽한 가용성이 아니라, 외부 API가 잠깐 흔들려도 사용자가 빈 오류화면 대신 안전한 수동 발주 작업을 계속할 수 있게 하는 것이다.
