# 샵플링 가격설정 Bulk 로드맵

## 목표

최대 20,000개의 `goods_key`를 카나리 검증 후 최대 50개 청크로 안전하게 순차 실행하고, 브라우저를 닫아도 작업 상태를 복구하며, 실패 상품만 제한적으로 재시도한다.

## 100점 기준 진행표

| 단계 | 누적 점수 | 상태 | 완료 기준 |
| --- | ---: | --- | --- |
| 1. 입력·검증·미리보기 | 15 | 완료 | CSV/XLSX/붙여넣기, 숫자 검증, 중복 제거, 20,000개 제한, 청크 예상 |
| 2. 준비 작업 영속 저장 | 35 | 완료 | Supabase job/items/chunks 원자적 저장, 최근 작업 및 상세 복구 |
| 3. 수동 카나리 실행·결과 확인 | 55 | 개발 완료·운영 적용 대기 | 실제 1~10개만 명시적 확인 후 실행, exact request_id 결과 저장, 일반 청크 자동 실행 금지 |
| 4. 일반 청크 수동 승인·직렬 실행 | 75 | 예정 | 카나리 성공 후 운영자 승인, 한 번에 한 청크, 중복 dispatch 차단 |
| 5. 실패 상품 제한 재시도·복구 | 90 | 예정 | 명시적 실패 goods_key만 재시도, 불명확 결과 차단, 일시중지·재개 |
| 6. 운영 검증·관측·정리 | 100 | 예정 | 소규모/중규모/대규모 검증, 진행률·감사 로그, 오래된 준비 작업 정리 |

## 안전 원칙

- 기존 50개 이하 즉시 실행기는 독립적으로 유지한다.
- 카나리와 일반 청크는 동일한 기존 가격설정 워크플로를 사용한다.
- 실제 쓰기 전 사용자 확인을 요구한다.
- exact `request_id` 결과만 수용한다.
- GitHub Actions 전송 응답이 불확실하면 재전송하지 않고 차단한다.
- 카나리 성공만으로 일반 청크를 자동 시작하지 않는다.
- 실패 상품을 특정할 수 없으면 전체 청크를 자동 재실행하지 않는다.
- Supabase service role은 서버에서만 사용한다.
