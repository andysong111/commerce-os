# 샵플링 가격설정 Bulk 로드맵

## 목표

최대 20,000개의 `goods_key`를 카나리 검증 후 최대 50개 청크로 안전하게 순차 실행하고, 브라우저를 닫아도 작업 상태를 복구하며, 실패 상품만 제한적으로 재시도한다. 마지막 운영 단계에서는 가격 무쓰기 부하검증, 리포트·감사 로그, 보관·복구 절차까지 표준화한다.

## 안전 원칙

- 기존 50개 이하 즉시 실행기는 독립적으로 유지한다.
- 카나리·일반·재시도 청크는 동일한 기존 가격설정 워크플로를 사용한다.
- 실제 쓰기 전 사용자 확인을 요구한다.
- exact `request_id` 결과만 수용한다.
- GitHub Actions 전송 응답이 불확실하면 재전송하지 않고 기존 결과만 확인한다.
- 카나리 성공만으로 일반 청크를 자동 시작하지 않는다.
- 실패 상품을 특정할 수 없으면 자동 재시도하지 않는다.
- 이미 성공한 상품은 재시도 대상에 포함하지 않는다.
- Supabase service role은 서버에서만 사용한다.
- 검증 전용 작업은 합성 goods_key만 사용하며 가격 실행 경로를 구조적으로 잠근다.
- 오래된 작업은 자동 삭제하지 않고 운영자가 확인 후 보관한다.

현재 공식 운영 점수는 **90/100**이다. 61개 직렬 실행, 실패 상품만 재시도, 현재 청크 완료 후 일시중지, 탭 종료·재접속 상태 복구, 재개 후 61/61 완료까지 운영 환경에서 검증했다.

## 5단계 — 완료된 운영 검증

- 정상 상품 9개와 의도적 실패 goods_key 1개를 함께 실행하여 실패 범위를 정확히 1개로 분리했다.
- 실패 상품 1개만 재실행했고 이미 성공한 9개는 재실행하지 않았다.
- 재시도 회차 제한과 자동 중단을 확인했다.
- 61개 작업에서 normal 50개가 실행 중일 때 일시중지를 요청했다.
- 현재 청크가 끝난 뒤 성공 60·대기 1 상태로 정지했다.
- 브라우저 탭을 닫고 같은 URL에 재접속했을 때 일시중지 상태가 복구됐다.
- 재개 후 마지막 1개만 실행되어 성공 61·실패 0·대기 0으로 완료됐다.

## 6단계 — 95점과 100점 통과 기준

### 95점

- 안전한 실제 상품 200~500개를 실행한다.
- 각 청크의 첫 상품·중간 상품·마지막 상품과 전체 첫·마지막 상품을 Shopling 수정일·가격으로 표본 확인한다.
- 전체 성공 수, 청크 수, 실행 순서, 처리시간, 누락·중복 여부를 운영 리포트와 대조한다.

### 100점

- 브라우저 로컬에서 합성 goods_key 20,000개를 실제 파서·청크 계획 함수로 검증한다.
- DB에 합성 goods_key 20,000개와 401개 청크를 가격 무쓰기 검증 전용 작업으로 저장하고 재접속한다.
- 검증 전용 작업에서 카나리·normal·retry 가격 실행 버튼과 외부 dispatch가 구조적으로 차단되는지 확인한다.
- 운영 리포트 JSON, 상품 결과 CSV, 감사 로그를 내려받아 내용과 민감정보 비노출을 확인한다.
- 완료·실패·검증 작업을 보관하고 복구한다.
- 오래된 미실행 준비·검증 작업을 수동 일괄 보관한다.
- 운영 절차서의 장애 대응 체크리스트를 실제 화면과 대조한다.
