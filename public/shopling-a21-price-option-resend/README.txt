Commerce OS · Shopling A21 Price/Option Resend v0.3.5

목적
- Commerce OS에서 Shopling 저장 가격 재조회까지 VERIFIED 된 GOODSKEY만 A21 쇼핑몰상품수정에서 마켓으로 수정전송합니다.
- 판매가와 옵션은 동시에 겹치지 않게 1개 작업씩 처리합니다.
- 마켓별 성공/실패 결과는 검증하지 않습니다.
- Shopling 결과 팝업의 실제 로딩이 끝난 뒤 다음 작업으로 진행합니다.

v0.3.5 핵심
- v0.3.4까지 결과창의 window.open/form target/자동 스크롤을 직접 조작했지만 실기에서 완료 감지가 계속 누락되고 결과창 중복 혼선 가능성이 확인됐습니다.
- v0.3.5는 Shopling 기본 결과창 생성/스크롤 동작을 전혀 변경하지 않습니다.
- Chrome background가 모든 브라우저 창/탭과 frame을 직접 조회합니다.
- 결과 팝업에서 '쇼핑몰 상품 수정 전송 결과', 총건수/성공건수/실패건수, 성공여부 등 결과표 증거를 찾습니다.
- 화면에 실제로 보이는 '처리중입니다' 또는 '잠시만 기다려주시기 바랍니다'가 남아 있으면 계속 기다립니다.
- 로딩 문구가 사라지고 document.readyState=complete인 결과화면의 크기/결과 블록 수가 약 1.8초 동안 안정적이면 SUCCEEDED 처리하고 다음 작업으로 진행합니다.
- '상품 수정 전송이 완료되었습니다.' footer는 더 이상 필요하지 않으므로 스크롤 위치와 무관합니다.
- 완료된 결과 탭은 현재 작업에 연결되므로 기존 closeManaged 흐름에서 정리됩니다.
- 새 실행 시작 전에는 남아 있는 Shopling popup 창을 정리합니다.
- 전체 실행은 모든 PRICE 배치를 먼저 처리한 뒤 OPTION 배치를 처리합니다.
- 205 GOODSKEY: 판매가 200 → 판매가 5 → 옵션 200 → 옵션 5.

안전장치
1) Shopling 저장 가격 VERIFIED가 아니면 시작하지 않습니다.
2) 배송정보 수정안함과 판매가/옵션 form 값은 송신 전에 검증합니다.
3) Shopling 원본 송신 함수 자체가 실패하거나 예상하지 못한 확인창이 나오면 해당 작업은 실패합니다.
4) 결과 팝업의 로딩이 끝나기 전에는 다음 송신으로 넘어가지 않습니다.
5) 개별 마켓 성공/실패 내용은 진행 차단 조건으로 사용하지 않습니다.

사용
1) 기존 확장프로그램을 제거하고 v0.3.5 ZIP을 설치합니다.
2) 현재 실행 중인 이전 버전은 안전 중지하고 남아 있는 Shopling 결과창을 닫습니다.
3) 먼저 1 GOODSKEY 안전 테스트를 실행합니다.
4) 판매가 결과창의 중앙 '처리중입니다' 로딩이 사라진 뒤 약 2초 내 판매가 SUCCEEDED → 옵션 송신으로 넘어가는지 확인합니다.
5) 옵션도 동일하게 로딩 종료 후 SUCCEEDED가 되면 전체 가격·옵션 수정전송을 실행합니다.

주의
- SUCCEEDED는 Shopling 결과 팝업의 로딩 종료와 결과화면 안정화까지 확인됐다는 의미이며 개별 마켓 최종 성공을 보증하지 않습니다.
