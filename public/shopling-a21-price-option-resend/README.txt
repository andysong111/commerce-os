Commerce OS · Shopling A21 Price/Option Resend v0.4.1

목적
- Commerce OS에서 Shopling 저장 가격 재조회까지 VERIFIED 된 GOODSKEY만 A21 쇼핑몰상품수정에서 마켓으로 수정전송합니다.
- 판매가와 옵션은 동시에 겹치지 않게 1개 작업씩 처리합니다.
- 마켓별 성공/실패 결과는 검증하지 않습니다.
- Chrome DevTools Protocol(CDP)로 실제 Shopling 결과창/프레임을 직접 읽어 처리중 로딩 종료를 확인한 뒤 다음 작업으로 진행합니다.

v0.4.1 핵심
- v0.2.7에서 옵션전송까지 정상적으로 이어졌던 completeJob → 다음 큐 실행 구조는 그대로 유지합니다.
- v0.3.x~v0.4.0에서 시도한 결과창 content-script/self-observer/A21 최종전송일 판정은 완료 조건에서 제거합니다.
- chrome.debugger 권한으로 실행 중 생성된 결과창 및 관련 Shopling 탭에 CDP를 직접 연결합니다.
- Runtime execution context를 수집해 top document뿐 아니라 child frame 실행 컨텍스트까지 직접 평가합니다.
- CDP evaluate에서 실제 결과문서를 맨 아래로 스크롤하고 '처리중입니다' / '잠시만 기다려주시기 바랍니다' / 결과표 / 완료 footer를 직접 읽습니다.
- 처리중 표시가 사라지고 결과표 또는 완료 footer가 1.8초 안정된 뒤에만 completeJob()을 호출합니다.
- 작업 완료 또는 안전 중지 시 debugger 연결은 자동으로 해제합니다.
- 결과 내용의 성공/실패, 도매창고/투비즈온 등 개별 마켓 실패는 진행 차단 조건으로 사용하지 않습니다.
- 전체 실행은 모든 PRICE 배치를 먼저 처리한 뒤 OPTION 배치를 처리합니다.
- 205 GOODSKEY: 판매가 200 → 판매가 5 → 옵션 200 → 옵션 5.

안전장치
1) Shopling 저장 가격 VERIFIED가 아니면 시작하지 않습니다.
2) 배송정보 수정안함과 판매가/옵션 form 값은 송신 전에 검증합니다.
3) Shopling 원본 송신 함수 자체가 실패하거나 예상하지 못한 확인창이 나오면 해당 작업은 실패합니다.
4) 현재 작업의 worker/popup opener 관계와 실행 중 생성된 탭을 이용해 결과 후보를 좁힙니다.
5) 여러 execution context 중 하나라도 처리중이면 다음 단계로 넘어가지 않습니다.
6) 결과표가 보여도 처리중 종료 또는 완료 footer 등 강한 완료 근거가 없으면 완료하지 않습니다.
7) CDP 완료 확인을 30분 동안 못하면 V041_CDP_RESULT_TIMEOUT으로 안전 중단합니다.

사용
1) 기존 확장프로그램을 제거하고 v0.4.1 ZIP을 설치합니다.
2) 이전 실행은 안전 중지하고 남아 있는 Shopling 결과창을 닫습니다.
3) 먼저 1 GOODSKEY 안전 테스트를 실행합니다.
4) 실행 중 Chrome에 '디버깅 중' 안내가 표시될 수 있습니다. 정상이며 작업 완료 후 자동 해제됩니다.
5) 확장 UI에서 'CDP로 실제 결과 타깃 탐색 중' → '실제 결과문서 처리중 직접 확인' → '실제 결과문서 로딩 종료 확인' → 판매가 SUCCEEDED → 옵션 송신 순서를 확인합니다.
6) 옵션도 같은 방식으로 완료되면 전체 가격·옵션 수정전송을 실행합니다.

주의
- SUCCEEDED는 Shopling 실제 결과문서의 로딩 종료까지 확인됐다는 의미이며 개별 마켓 최종 성공을 보증하지 않습니다.
