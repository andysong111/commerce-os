Commerce OS · Shopling A21 Price/Option Resend v0.3.9

목적
- Commerce OS에서 Shopling 저장 가격 재조회까지 VERIFIED 된 GOODSKEY만 A21 쇼핑몰상품수정에서 마켓으로 수정전송합니다.
- 판매가와 옵션은 동시에 겹치지 않게 1개 작업씩 처리합니다.
- 마켓별 성공/실패 결과는 검증하지 않습니다.
- 결과 팝업의 로딩 감지 대신 A21 목록의 최종전송일 갱신을 확인한 뒤 다음 작업으로 진행합니다.

v0.3.9 핵심
- v0.2.7에서 실제 옵션전송까지 정상적으로 넘어갔던 completeJob → 다음 큐 실행 구조는 그대로 유지합니다.
- v0.3.0~v0.3.8에서 결과 팝업의 DOM, 완료문구, about:blank, 네트워크 무통신, 처리중 표시를 감지하려 했으나 실기 Shopling 결과창 구조 때문에 안정적으로 완료 판정하지 못했습니다.
- v0.3.9는 결과 팝업을 완료 판정의 핵심 경로에서 제거합니다.
- 상품수정 전송창을 열기 직전 대상 GOODSKEY의 A21 목록 '최종전송일'을 기준값으로 저장합니다.
- 송신 ACK 이후 원래 A21 작업창에서 같은 GOODSKEY 검색을 자동으로 다시 실행합니다.
- 결과 행의 '최종전송일' 헤더를 찾아 각 GOODSKEY의 시간을 읽고, 헤더 직접 매핑이 안 되면 행의 마지막 날짜/시간을 fallback으로 사용합니다.
- 대상 GOODSKEY 전부의 최종전송일이 기준값보다 새로워졌거나 송신시각의 최근시간으로 갱신된 것이 확인되면 SUCCEEDED 처리합니다.
- 확인 후에만 기존 completeJob()을 호출하므로 현재 작업창을 정리하고 다음 판매가/옵션 큐로 진행합니다.
- 전체 실행은 모든 PRICE 배치를 먼저 처리한 뒤 OPTION 배치를 처리합니다.
- 205 GOODSKEY: 판매가 200 → 판매가 5 → 옵션 200 → 옵션 5.

안전장치
1) Shopling 저장 가격 VERIFIED가 아니면 시작하지 않습니다.
2) 배송정보 수정안함과 판매가/옵션 form 값은 송신 전에 검증합니다.
3) Shopling 원본 송신 함수 자체가 실패하거나 예상하지 못한 확인창이 나오면 해당 작업은 실패합니다.
4) 송신 후 A21 목록을 자동 재검색하고 대상 GOODSKEY 전체의 최종전송일 갱신을 확인합니다.
5) 일부 GOODSKEY만 갱신되면 다음 작업으로 넘어가지 않습니다.
6) 결과 팝업 로딩/스크롤/개별 마켓 성공실패는 진행 차단 조건으로 사용하지 않습니다.
7) 최종전송일 갱신을 30분 동안 확인하지 못하면 V039_FINAL_SEND_READBACK_TIMEOUT으로 안전 중단합니다.

사용
1) 기존 확장프로그램을 제거하고 v0.3.9 ZIP을 설치합니다.
2) 현재 실행 중인 이전 버전은 안전 중지하고 남아 있는 Shopling 결과창을 닫습니다.
3) 먼저 1 GOODSKEY 안전 테스트를 실행합니다.
4) 판매가 송신 후 확장 UI에 'A21 최종전송일 재조회 중' 또는 '최종전송일 갱신 확인 1/1'이 표시되는지 확인합니다.
5) 판매가 최종전송일이 최근시간으로 바뀌면 판매가 SUCCEEDED → 옵션 송신으로 넘어가는지 확인합니다.
6) 옵션도 같은 방식으로 완료되면 전체 가격·옵션 수정전송을 실행합니다.

주의
- SUCCEEDED는 A21의 최종전송일이 최근시간으로 갱신됐다는 의미이며 개별 마켓 최종 성공을 보증하지 않습니다.
