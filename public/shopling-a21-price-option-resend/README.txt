Commerce OS · Shopling A21 Price/Option Resend v0.3.8

목적
- Commerce OS에서 Shopling 저장 가격 재조회까지 VERIFIED 된 GOODSKEY만 A21 쇼핑몰상품수정에서 마켓으로 수정전송합니다.
- 판매가와 옵션은 동시에 겹치지 않게 1개 작업씩 처리합니다.
- 마켓별 성공/실패 결과는 검증하지 않습니다.
- Shopling 결과창의 실제 로딩이 끝난 뒤에만 다음 작업으로 진행합니다.

v0.3.8 핵심
- v0.2.7에서 실제 옵션전송까지 정상적으로 넘어갔던 completeJob → 다음 큐 실행 구조를 그대로 유지합니다.
- v0.3.7의 네트워크 무통신 판정은 실제 Shopling '처리중입니다' 로딩이 남아 있는데도 너무 일찍 SUCCEEDED가 되어 결과창을 닫을 수 있었습니다.
- v0.3.8은 네트워크 종료 자체를 완료 조건으로 사용하지 않습니다.
- Chrome webRequest 이벤트는 현재 작업이 만든 실제 Shopling 결과 탭을 특정하는 용도로만 사용합니다.
- 특정된 결과 탭을 chrome.scripting.executeScript로 직접 읽어 '처리중입니다' 또는 '잠시만 기다려주시기 바랍니다' 표시를 실제로 관찰합니다.
- 해당 처리중 표시가 실제로 한 번 확인된 뒤 사라지고, 결과표가 남아 있는 상태가 약 1.8초 안정되어야 SUCCEEDED 처리합니다.
- 처리중 표시가 사라지기 전에는 결과창을 닫지 않고 다음 옵션전송도 시작하지 않습니다.
- 결과 내용의 성공/실패, 도매창고/투비즈온 등 개별 마켓 실패는 진행 차단 조건으로 사용하지 않습니다.
- 전체 실행은 모든 PRICE 배치를 먼저 처리한 뒤 OPTION 배치를 처리합니다.
- 205 GOODSKEY: 판매가 200 → 판매가 5 → 옵션 200 → 옵션 5.

안전장치
1) Shopling 저장 가격 VERIFIED가 아니면 시작하지 않습니다.
2) 배송정보 수정안함과 판매가/옵션 form 값은 송신 전에 검증합니다.
3) Shopling 원본 송신 함수 자체가 실패하거나 예상하지 못한 확인창이 나오면 해당 작업은 실패합니다.
4) 실제 결과창에서 '처리중입니다' 표시를 한 번도 관찰하지 못하면 조기 완료하지 않습니다.
5) 실제 처리중 표시가 사라지기 전에는 completeJob()을 호출하지 않으므로 Shopling 창도 닫지 않습니다.
6) 결과창 DOM 접근이 불가능하면 안전하게 대기하며 조기 완료하지 않습니다.
7) 로딩 종료를 30분 동안 확인하지 못하면 V038_VISIBLE_LOADING_TIMEOUT으로 안전 중단합니다.

사용
1) 기존 확장프로그램을 제거하고 v0.3.8 ZIP을 설치합니다.
2) 현재 실행 중인 이전 버전은 안전 중지하고 남아 있는 Shopling 결과창을 닫습니다.
3) 먼저 1 GOODSKEY 안전 테스트를 실행합니다.
4) 판매가 송신 후 확장 UI에서 '실제 결과창 로딩 중 확인 · 처리중입니다 종료까지 창 유지'가 표시되는지 확인합니다.
5) Shopling 로딩이 실제로 사라진 뒤 '실제 로딩 종료 감지 · 안정화' → 판매가 SUCCEEDED → 옵션 송신 순서가 되는지 확인합니다.
6) 옵션도 같은 방식으로 완료되면 전체 가격·옵션 수정전송을 실행합니다.

주의
- SUCCEEDED는 Shopling 결과창의 실제 처리중 표시 종료까지 확인됐다는 의미이며 개별 마켓 최종 성공을 보증하지 않습니다.
