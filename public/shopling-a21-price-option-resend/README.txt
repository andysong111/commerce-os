Commerce OS · Shopling A21 Price/Option Resend v0.2.5

목적
- Commerce OS에서 Shopling 쇼핑몰별 가격 재조회까지 VERIFIED 된 GOODSKEY만 A21 쇼핑몰상품수정에서 마켓으로 수정전송합니다.
- 판매가 전송과 옵션 전송은 서로 별도 작업으로 실행합니다.
- 정확도 우선으로 동시 1개 작업만 직렬 실행합니다.
- 전체 실행 전 1 GOODSKEY 안전 테스트를 지원합니다.

실제 Shopling form 기준
- 판매가 모드: modify_tp=goods_normal
- 쇼핑몰별 판매가 source: tsmt_sale_price_tp=J 필수
- 판매가 수정: trsmt_env_mody_price=Y
- 배송정보: 실제 '수정안함' 라디오를 DOM 라벨/onclick 증거로 식별해 고정
- 상품명/카테고리/이미지/수수료/상세설명/키워드/유료서비스는 수정안함
- 옵션 모드: modify_tp=goods_stock
- 옵션송신: trsmt_env_mody_opt=1
- 최종 송신함수: goods_mallMdfy_submit_sp()

v0.2.5 변경
- v0.2.4의 배송정보 수정안함 고정과 결과창 이동/닫힘 추적을 유지합니다.
- 실행 시작 시 이미 열려 있던 Shopling 탭을 기준선으로 저장합니다.
- 송신 이후 새로 생긴 Shopling 탭/창과 관리 중인 탭의 모든 프레임을 결과 후보로 검사합니다.
- 결과 화면의 첫 번째 성공건수/실패건수만 보지 않고 쇼핑몰별 결과 블록 전체를 파싱합니다.
- 각 쇼핑몰의 총건수·성공건수·실패건수를 합산합니다.
- 상품그룹별 예상 연결 쇼핑몰 수에 도달하고 모든 총건수가 처리된 뒤에만 성공/실패를 확정합니다.
- 실패 시 도매창고/투비즈온 등 실패 쇼핑몰명과 가능한 실패 메시지를 확장프로그램 상태창에 표시합니다.
- 모든 결과를 끝까지 확인하지 못하면 V025_RESULT_TIMEOUT으로 fail-closed 처리합니다.

안전장치
1) Shopling 가격 재조회가 VERIFIED가 아니면 실행하지 않습니다.
2) 처음에는 '1 GOODSKEY 안전 테스트'로 판매가→옵션 2개 작업만 검증할 수 있습니다.
3) 판매가 송신 직전 배송정보=수정안함을 MAIN world까지 재검증합니다.
4) 기존에 열려 있던 Shopling 결과창을 현재 작업 성공으로 잘못 인식하지 않도록 실행 시작 기준선을 사용합니다.
5) 한 쇼핑몰이라도 실패하면 해당 작업은 V025_RESULT_PARTIAL_FAILURE로 기록합니다.
6) 성공/실패 결과 근거가 없으면 성공으로 기록하지 않습니다.

사용
1) 기존 A21 Resend를 제거하고 v0.2.5 ZIP 압축을 풉니다.
2) chrome://extensions → 개발자 모드 → '압축해제된 확장 프로그램을 로드합니다'.
3) Shopling 로그인 상태에서 A18 또는 A21 화면 하나를 엽니다.
4) 먼저 '1 GOODSKEY 안전 테스트'를 실행합니다.
5) 판매가/옵션의 Shopling 결과 집계와 실패 쇼핑몰명을 확인합니다.
6) 판매가/옵션 모두 SUCCEEDED 확인 후 전체 실행을 사용합니다.

주의
- 이 확장프로그램은 실제 마켓 수정전송을 실행합니다.
- [999] 소비자가는 공급가보다 크게 입력해주세요 같은 마켓별 가격 검증 실패는 배송정보 문제와 별개의 마켓 가격 규칙 오류입니다.
