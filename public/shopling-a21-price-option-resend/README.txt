Commerce OS · Shopling A21 Price/Option Resend v0.3.4

목적
- Commerce OS에서 Shopling 저장 가격 재조회까지 VERIFIED 된 GOODSKEY만 A21 쇼핑몰상품수정에서 마켓으로 수정전송합니다.
- 판매가와 옵션은 동시에 겹치지 않게 1개 작업씩 처리합니다.
- 마켓별 성공/실패 결과는 검증하지 않습니다.
- Shopling 결과창의 '상품 수정 전송이 완료되었습니다.' 확인 후 다음 작업으로 진행합니다.

v0.3.4 핵심
- v0.3.3에서 window.open만 추적했으나 실제 Shopling은 form target 방식으로 결과창을 만들 수 있어 결과창을 놓치는 사례가 확인됐습니다.
- Shopling 원본 송신 함수 goods_mallMdfy_submit_sp를 MAIN world에서 감싸 동일 함수가 5초 안에 중복 호출되면 두 번째 실제 송신을 차단합니다.
- 송신 순간 HTML form submit/requestSubmit/submit 이벤트를 가로채 form target 결과창을 직접 확보합니다.
- target=_blank이면 고유 이름으로 바꿔 동일 결과창 1개를 사용하게 하고, named target이면 해당 창을 직접 재사용합니다.
- 확보한 결과창과 내부 frame/window/body/스크롤 컨테이너를 300ms마다 끝까지 자동 스크롤합니다.
- '상품 수정 전송이 완료되었습니다.'가 나타나고 처리중 문구가 사라지면 즉시 SUCCEEDED 처리 후 다음 작업을 시작합니다.
- 완료된 결과창은 신호 후 자동으로 닫고, 새 실행 시작 전에는 남아 있는 Shopling 팝업 창도 정리합니다.
- 전체 실행은 모든 PRICE 배치를 먼저 처리한 뒤 OPTION 배치를 처리합니다.
- 205 GOODSKEY: 판매가 200 → 판매가 5 → 옵션 200 → 옵션 5.

안전장치
1) Shopling 저장 가격 VERIFIED가 아니면 시작하지 않습니다.
2) 배송정보 수정안함과 판매가/옵션 form 값은 송신 전에 검증합니다.
3) 같은 Shopling 송신 함수의 5초 내 중복 실행은 두 번째 실제 송신을 차단합니다.
4) Shopling 원본 송신 함수 자체가 실패하거나 예상하지 못한 확인창이 나오면 해당 작업은 실패합니다.
5) 완료문구가 나타나기 전에는 다음 송신으로 넘어가지 않습니다.

사용
1) 기존 확장프로그램을 제거하고 v0.3.4 ZIP을 설치합니다.
2) 현재 실행 중인 이전 버전은 안전 중지합니다.
3) 먼저 1 GOODSKEY 안전 테스트를 실행합니다.
4) 판매가 결과창이 1개만 생성되고 자동으로 아래로 이동하는지 확인합니다.
5) 완료문구 → 판매가 SUCCEEDED → 옵션 송신 → 완료문구 → 옵션 SUCCEEDED 순서인지 확인합니다.
6) 정상이라면 전체 가격·옵션 수정전송을 실행합니다.

주의
- SUCCEEDED는 Shopling 수정전송 결과창의 완료문구가 확인됐다는 의미이며 개별 마켓 최종 성공을 보증하지 않습니다.
