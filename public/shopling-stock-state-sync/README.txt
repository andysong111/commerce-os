Commerce OS · Shopling Stock State Sync v0.3.1

사용자 준비
- Stock State Sync 구버전은 모두 제거/비활성화하고 v0.3.1 하나만 사용합니다.
- Shopling에 로그인 완료한 관리자 메인 탭 하나와 Commerce OS 재고·품절·재입고 탭을 열어둡니다.
- 로그인 폼만 열린 상태는 실행할 수 없습니다.
- A4/A6/A21은 미리 열 필요가 없습니다. 실행 시 전용 작업창을 자동 생성합니다.
- 원본 관리자 탭은 새로고침하거나 이동하지 않습니다.
- 재고 0 기준점은 다시 만들지 않고 1건 안전 실행만 합니다.

실행
- 옵션: 자동 생성 A6 → 옵션자체관리코드 B코드 정확검색 → 정확 1행 옵션상태 품절/판매중 → 자동 생성 A21 → 샵플링상품코드 goods key 정확검색 → 옵션송신.
- 단품: 자동 생성 A4 → goods key 정확검색 → 상품상태 품절/판매중 → 자동 생성 A21 → 상품판매상태송신.
- A22 및 마켓 재고수량 동기화는 사용하지 않습니다.
- 검색기간은 A4/A6/A21 모두 2024-01-01~실행 당일(한국 시간)이며 실제 입력값을 검증합니다.
- 상태변경 전에 필요한 두 작업화면, 실행코드 연결, 날짜 입력칸을 모두 점검합니다.
- 실패·결과불확실 작업창은 확인을 위해 그대로 둡니다. 최종 결과 확인 전 성공 처리하지 않습니다.

v0.3.1 검색결과 인식 보강
- v0.3.0 실환경 Canary에서 A6 날짜설정과 B코드 검색은 성공했고 화면에 정확 1행이 보였지만 worker가 결과 없음으로 오판했습니다.
- 가격조정 확장의 검증된 행 탐색 방식처럼 legacy tr에 visibility 조건을 강제하지 않고, 정확 토큰 + checkbox 계약으로 결과행을 식별합니다.
- Shopling 내부 frame이 검색 후 다시 로드되는 경우 이어받은 worker가 결과표 재도색을 최대 20초 기다립니다. 최초 검색 직후에는 최대 30초 기다립니다.
- 화면의 총 조회수가 1건 이상인데 정확 행 연결이 실패하면 EXACT_RESULT_ROW_NOT_BOUND로 별도 진단해 실제 0건과 구분합니다.
- 이 변경은 검색/행 인식만 수정하며 옵션/상품 상태변경, A21 전송, 재고수량 계산은 바꾸지 않습니다.

구현/배포
- 가격조정 확장의 새 작업창 생성 + background all-frame 직접탐색 패턴을 재사용합니다. 가격 확장 자체는 수정하지 않았습니다.
- content-shopling-v018.js 상태변경 템플릿은 유지하고 search-policy-v023.js를 ZIP 생성 시 결합합니다.
- A6는 background가 실제 '옵션자체관리코드' select option이 있는 frame을 직접 찾습니다.
- 재고·발주·취소·반품 데이터와 계산 로직은 수정하지 않습니다.
