Commerce OS · Shopling Stock State Sync v0.1.2

목적
- Commerce OS에서 실제 품절을 확인한 B코드의 Shopling 상태를 품절로 동기화합니다.
- 품절 0 기준점 이후 확정입고로 재고가 1개 이상이 되면 반대로 판매중으로 복구합니다.
- Shopling의 메뉴/본문이 서로 다른 프레임에 있는 구조를 인식해 실제 작업 프레임으로 안전하게 이동합니다.
- v0.1.2부터 메뉴 이름이 정확히 일치하고 경로 후보가 하나로 검증될 때만 A6/A22/A21 이동을 허용합니다.

실행 경로
1) 옵션상품
   A6 옵션대량수정: 옵션자체관리코드로 B코드 검색 → 정확 일치 1행만 선택 → 옵션상태 품절/판매중 → 일괄 상태변경
   A22 쇼핑몰상품옵션전송: 동일 B코드 검색 → 정확 일치 1행만 선택 → 상품옵션전송 → 최종 완료문구 확인

2) 옵션 없는 단품
   A6 옵션대량수정: 옵션자체관리코드로 B코드 검색 → 옵션상태 품절/판매중 → 일괄 상태변경
   A21 쇼핑몰상품수정: 모델번호 검색 → 정확 일치 1행만 선택 → 상품 수정전송 → 상품판매상태송신 → 품절/판매중 → 상품수정 송신 → 최종 완료문구 확인
   단품은 A22 옵션전송만으로 품절/판매중을 확정하지 않습니다.

v0.1.2 안전 보강
- A6 메뉴는 '옵션대량수정' 정확 메뉴만 허용하며 '옵션상품수정' 같은 유사 메뉴를 선택하지 않습니다.
- 직전 오진입으로 확인된 prodBulkOptLst.phtml 경로는 메뉴 후보에서 명시적으로 제외합니다.
- 동일 단계에서 서로 다른 메뉴 경로가 2개 이상 보이면 임의로 첫 번째를 누르지 않고 중단합니다.
- Shopling이 '페이지 접근권한이 없습니다.' 경고를 내면 현재 작업을 즉시 FAILED로 종료하고 자동 재시도를 차단합니다.
- 접근권한 경고 감지는 원장 재고값이나 품절 기준점을 변경하지 않습니다.

안전 규칙
- Commerce OS 화면의 1건 안전 실행에서만 시작합니다.
- 동시에 한 B코드만 실행합니다.
- 같은 B코드의 품절과 판매중 작업을 동시에 실행하지 않습니다.
- 정확 일치 B코드/모델번호 행이 정확히 1건일 때만 외부 변경을 진행합니다.
- 다른 행은 선택 해제합니다.
- 최종 완료문구 전에 성공 처리하지 않습니다.
- Shopling 처리 완료 후 실패건수가 있거나 제한시간이 지나면 UNCERTAIN/FAILED로 기록하고 수동 확인을 요구합니다.
- Chrome debugger 권한을 사용하지 않습니다.
- 확장프로그램은 1688 주문·결제, 가격, 상품명, 배송정보를 수정하지 않습니다.

설치/업데이트
1. Commerce OS 재고·품절·재입고 화면에서 v0.1.2 ZIP을 다운로드합니다.
2. ZIP 압축을 새 폴더에 풉니다.
3. chrome://extensions 에서 개발자 모드를 켭니다.
4. 기존 v0.1.1 확장은 제거하거나 비활성화하고, 압축해제된 v0.1.2 폴더를 로드합니다.
5. Commerce OS 재고·품절·재입고 화면과 로그인된 Shopling 탭을 새로고침합니다.
6. 실제 품절이 확인된 옵션상품 1건으로 먼저 검증합니다.
7. 단품 1건과 입고 후 판매중 복구 1건은 각각 별도 Canary로 검증합니다.
