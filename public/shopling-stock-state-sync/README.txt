Commerce OS · Shopling Stock State Sync v0.2.3.1

사용자 준비
- Stock State Sync 구버전은 모두 제거/비활성화하고 v0.2.3.1 하나만 사용합니다.
- Shopling에 로그인 완료한 관리자 메인 탭 하나와 Commerce OS 재고·품절·재입고 탭을 열어둡니다.
- 로그인 폼(아이디/비밀번호 입력 화면)만 열린 상태는 실행할 수 없습니다.
- A4/A6/A21을 미리 열 필요가 없습니다. 실행 시 전용 작업창을 자동 생성합니다.
- 원본 관리자 탭을 새로고침하거나 이동하지 않습니다.
- BZZ341-1 재고 0 기준점은 다시 만들지 않고 1건 안전 실행만 합니다.

실행
- 옵션: 자동 생성 A6 → 옵션자체관리코드 B코드 정확검색 → 정확 1행 옵션상태 품절/판매중 → 자동 생성 A21 → 샵플링상품코드 goods key 정확검색 → 옵션송신.
- 단품: 자동 생성 A4 → goods key 정확검색 → 상품상태 품절/판매중 → 자동 생성 A21 → 상품판매상태송신.
- A22 및 마켓 재고수량 동기화는 사용하지 않습니다.
- 검색기간은 A4/A6/A21 모두 2024-01-01~실행 당일(한국 시간)입니다. 실제 입력값을 검증합니다.
- 검색결과 []를 완료로 오인하지 않고, 내부 프레임이 검색 후 이동하면 저장한 검색정보로 이어갑니다.
- 상태변경 전에 필요한 두 작업화면, 실행코드 연결, 날짜 입력칸을 모두 점검합니다.
- 본 실행이 생성한 작업창/하위 결과창만 작업·완료 증거로 인정합니다. 다른 가격조정 작업 결과는 인정하지 않습니다.
- 실패·결과불확실 작업창은 확인을 위해 그대로 둡니다. 최종 결과 확인 전 성공 처리하지 않습니다.

v0.2.3.1 A6 frame bridge hotfix
- Shopling 레거시 화면에서 A6 제목/메뉴 프레임과 실제 검색 폼 프레임이 분리될 수 있습니다.
- 실제 검색 폼 프레임에 '옵션자체관리코드' 선택항목과 상품검색 입력 힌트가 함께 있을 때만, 화면에 영향을 주지 않는 off-screen 역할 마커를 추가합니다.
- 배경 all-frame 탐색과 기존 상태변경 worker가 같은 실제 A6 검색 프레임을 인식하도록 보조합니다.
- 가짜 검색 컨트롤, 상품 상태변경, 재고수량 변경은 만들거나 수행하지 않습니다.
- A6 인식 후에야 2024-01-01~오늘 날짜 사전검증과 실제 B코드 검색으로 넘어갑니다.
- 이 버전도 로그인된 실환경 Canary 검증이 필요합니다. 배포·모의테스트 통과가 마켓 전송 완료를 뜻하지 않습니다.

구현/배포
- 기존 가격 전송 background-v020.js의 새 작업창 생성/all-frame 탐색 패턴을 사용합니다. 가격 확장 소스 자체는 수정하지 않았습니다.
- public/.../content-shopling-v018.js는 변경하지 않은 상태변경 템플릿입니다.
- scripts/build-shopling-stock-worker-v023.mjs가 템플릿에 search-policy-v023.js와 좁은 검색/메시지 수정만 결합해 content-shopling-v023.js를 ZIP 안에 생성합니다.
- a6-frame-bridge-v0231.js는 실제 A6 검색 컨트롤이 존재하는 프레임에만 역할 인식 힌트를 추가합니다.
- 템플릿 앵커가 바뀌면 빌드가 실패하며, 모든 JS 구문과 manifest 파일 참조를 검사합니다. 저장소 폴더 직접 로드 대신 운영 다운로드 ZIP을 사용하세요.
- ?verify=1은 실제 ZIP 생성 검사 결과(버전, 파일목록, worker SHA256)만 반환합니다. 고객·상품 데이터가 없습니다.
- 재고·발주·취소·반품 데이터와 계산 로직, 기존 가격조정 확장은 수정하지 않습니다.
