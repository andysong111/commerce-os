Commerce OS · Shopling Stock State Sync v0.2.3.2

사용자 준비
- Stock State Sync 구버전은 모두 제거/비활성화하고 v0.2.3.2 하나만 사용합니다.
- Shopling에 로그인 완료한 관리자 메인 탭 하나와 Commerce OS 재고·품절·재입고 탭을 열어둡니다.
- 로그인 폼만 열린 상태는 실행할 수 없습니다.
- A4/A6/A21은 미리 열 필요가 없습니다. 실행 시 전용 작업창을 자동 생성합니다.
- 원본 관리자 탭은 새로고침하거나 이동하지 않습니다.
- BZZ341-1 재고 0 기준점은 다시 만들지 않고 1건 안전 실행만 합니다.

실행
- 옵션: 자동 생성 A6 → 옵션자체관리코드 B코드 정확검색 → 정확 1행 옵션상태 품절/판매중 → 자동 생성 A21 → 샵플링상품코드 goods key 정확검색 → 옵션송신.
- 단품: 자동 생성 A4 → goods key 정확검색 → 상품상태 품절/판매중 → 자동 생성 A21 → 상품판매상태송신.
- A22 및 마켓 재고수량 동기화는 사용하지 않습니다.
- 검색기간은 A4/A6/A21 모두 2024-01-01~실행 당일(한국 시간)이며 실제 입력값을 검증합니다.
- 상태변경 전에 필요한 두 작업화면, 실행코드 연결, 날짜 입력칸을 모두 점검합니다.
- 실패·결과불확실 작업창은 확인을 위해 그대로 둡니다. 최종 결과 확인 전 성공 처리하지 않습니다.

v0.2.3.2 A6 unique-control hotfix
- 실제 Canary에서 A6 화면은 열렸지만 제목/경로/검색-input 힌트가 서로 다른 legacy frame에 분리돼 역할 인식이 실패했습니다.
- A6 검색 프레임의 고유한 select option인 '옵션자체관리코드' 존재 자체를 역할 신호로 사용합니다.
- bridge는 off-screen 역할 마커만 추가하며 클릭, 선택, 상태변경, 재고수량 변경을 수행하지 않습니다.
- A6 인식 후에야 2024-01-01~오늘 날짜 검증과 B코드 검색으로 넘어갑니다.
- 로그인된 실환경 A6→A21 Canary는 여전히 최종 검증이 필요합니다.

구현/배포
- 기존 가격 전송 확장의 새 작업창 생성/all-frame 탐색 패턴을 재사용합니다. 가격 확장 자체는 수정하지 않았습니다.
- content-shopling-v018.js 상태변경 템플릿은 유지하고 search-policy-v023.js를 ZIP 생성 시 결합합니다.
- a6-frame-bridge-v0231.js는 실제 '옵션자체관리코드' select option이 존재하는 frame에만 역할 인식 힌트를 추가합니다.
- 재고·발주·취소·반품 데이터와 계산 로직은 수정하지 않습니다.
