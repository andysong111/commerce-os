Commerce OS Shopling Market Fresh Worker Canary v0.3.2

목적
- Shopling 마켓 자동전송을 대량화하기 전에 신규상품 1개의 남은 DM1~DM4 / SM1~SM2 채널을 실전 검증합니다.
- 채널 1건마다 이전 관리자/팝업 창을 재사용하지 않고 새 관리자 작업창에서 [A18]부터 다시 시작합니다.
- 이미 sent 처리된 채널은 서버 원장에서 다시 claim되지 않습니다.

필수 시작 상태
- 사용자가 평소 로그인 후 계속 열어두는 https://shopling.co.kr/index.php 메인 탭 1개를 유지합니다.
- 이 메인 탭은 Fresh Worker의 고정 런처이며 자동화가 새로 만들거나 닫지 않습니다.
- 사용자가 보고 있는 Shopling [A18] 쇼핑몰상품등록 탭은 컨트롤/상태 탭으로 유지합니다.
- 탭 순서, 활성 탭, Windows 가상 데스크톱 위치는 중요하지 않습니다.
- 기존 운영용 Commerce OS Shopling Bridge는 OFF로 둡니다.

v0.3.2 런처 안전계약
1. 기존 로그인 Shopling 메인(index.php) 탭을 URL로 찾습니다.
2. 이전 실패로 해당 탭이 /form/login_proc.php 흰 화면에 있으면 index.php로 자동 복구합니다.
3. Shopling 도메인 팝업을 잠시 허용합니다.
4. 기존 로그인 메인 탭의 관리자접속을 자동 클릭합니다.
5. 새 관리자 팝업이 실제로 생성됐는지 최대 8초 확인합니다.
6. 관리자 팝업이 확인되면 팝업 허용을 즉시 해제하고 런처가 index.php인지 다시 복구/확인합니다.
7. 관리자 팝업이 확인되지 않으면 시장 송신 단계로 가지 않고 run의 송신 전 claim 전체를 queued로 원복합니다.
8. 새 관리자 팝업만 작업창으로 등록하고 원래 로그인 런처 탭은 절대 닫지 않습니다.

채널 순환
1. 새 관리자 창에서 [18] 쇼핑몰상품등록으로 진입합니다.
2. 현재 채널의 자사상품코드로 미등록 검색합니다.
3. 같은 행의 Shopling goods_key(상품번호) + 자사상품코드가 모두 정확히 일치해야 선택합니다.
4. 해당 도매/소매 저장검색을 ID 선택 화면과 연동정보 화면에 각각 적용합니다.
5. 상품등록송신 직전에 Commerce OS durable submit lock을 획득합니다.
6. 실제 /prod_a/prod_rgst_rspt.phtml 결과 페이지가 처리완료되고 성공건수>0, 실패건수=0일 때만 sent 기록합니다.
7. 성공하면 방금 사용한 관리자 작업창만 닫고, 같은 기존 Shopling 메인 탭에서 다시 관리자접속을 실행해 다음 채널용 관리자 창을 엽니다.
8. 송신 전 실패는 현재/미시작 채널을 queued로 원복합니다.
9. 송신 경계 이후 결과가 불명확하면 confirm_needed로 멈추며 자동 재송신하지 않습니다.

운영 주의
- 기존 로그인 Shopling 메인(index.php) 런처 탭과 원래 A18 컨트롤 탭을 닫지 않습니다.
- 다른 탭에서 작업하거나 Windows 가상 데스크톱을 이동하는 것은 괜찮습니다.
- 로그인 런처가 없으면 새 공개 메인창을 만들지 않고 안전중단합니다.
- 확인필요가 뜨면 다시 버튼을 누르지 않습니다.
