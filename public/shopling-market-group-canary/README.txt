Commerce OS Shopling Market Parallel Fresh Worker Canary v0.3.4

목적
- Shopling 마켓 자동전송을 대량화하기 전에 신규상품 1개의 남은 DM1~DM4 / SM1~SM2 채널을 실전 검증합니다.
- 공개 Shopling 메인, 관리자접속 버튼, 로그인 팝업 경로를 사용하지 않습니다.
- 현재 정상 로그인되어 열려 있는 A18 쇼핑몰상품등록 탭을 원본 템플릿으로 유지합니다.
- 남은 채널마다 A18 복제 작업창을 1개씩 만들고 모두 동시에 진행합니다.

필수 시작 상태
- Shopling [A18] 쇼핑몰상품등록 탭 1개를 정상 로그인 상태로 열어둡니다.
- 이 A18 탭은 원본 컨트롤 탭이며 자동 검색/선택/송신에 사용하지 않습니다.
- 기존 운영용 Commerce OS Shopling Bridge는 OFF로 둡니다.
- 탭 순서, 활성 탭, 다른 업무, Windows 가상 데스크톱 위치는 중요하지 않습니다.

v0.3.4 병렬 안전계약
1. 버튼을 누른 A18 탭 ID를 원본 컨트롤 탭으로 고정합니다.
2. 남은 채널 각각에 대해 chrome.tabs.duplicate()로 같은 원본 A18을 복제합니다.
3. 도매4·소매1·소매2가 남았다면 복제 작업창 3개를 각각 생성하고 병렬로 진행합니다.
4. 각 작업창은 goods_key + 자사상품코드 + 채널 프로필로 자기 작업만 처리합니다.
5. 한 채널이 송신 전에 실패해도 그 채널만 queued로 원복하고 다른 병렬 채널은 계속 진행합니다.
6. 한 채널이 송신 경계 이후 불명확하면 그 창만 confirm_needed로 보존하며 다른 채널은 계속 진행합니다.
7. 실제 결과 페이지에서 비셀파 쇼핑몰의 성공이 확인되고 비셀파 실패가 없을 때 sent로 기록합니다.
8. 셀파 단독 실패는 운영정책상 성공 판정을 막지 않습니다. 셀파 외 실패는 해당 채널만 확인필요로 멈춥니다.
9. 성공한 채널의 복제 작업창만 닫습니다. 원본 A18과 다른 채널 복제창은 건드리지 않습니다.

채널별 처리
1. 복제 A18 작업창에서 해당 채널 자사상품코드로 미등록 검색합니다.
2. 같은 행의 Shopling goods_key + 자사상품코드가 모두 정확히 일치해야 선택합니다.
3. 해당 도매/소매 저장검색을 ID 선택 화면과 연동정보 화면에 각각 적용합니다.
4. 상품등록송신 직전에 해당 goods_key의 durable submit lock을 획득합니다.
5. 실제 /prod_a/prod_rgst_rspt.phtml 결과 페이지를 확인합니다.
6. 성공한 작업창은 종료하고 다른 병렬 작업창은 독립적으로 계속됩니다.

운영 주의
- 원본 A18 탭과 Chrome 자체는 닫지 않습니다.
- 복제 작업창은 자동화가 닫을 수 있으므로 그 안에서 다른 업무를 하지 않습니다.
- 확인필요로 남은 창은 자동으로 다시 송신하지 않습니다.
