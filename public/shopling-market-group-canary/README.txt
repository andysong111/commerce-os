Commerce OS Shopling Market Fresh Worker Canary v0.3.3

목적
- Shopling 마켓 자동전송을 대량화하기 전에 신규상품 1개의 남은 DM1~DM4 / SM1~SM2 채널을 실전 검증합니다.
- 공개 Shopling 메인, 관리자접속 버튼, 로그인 팝업 경로를 자동화 흐름에서 제거합니다.
- 현재 정상 로그인되어 열려 있는 A18 쇼핑몰상품등록 탭 자체를 원본 템플릿으로 사용합니다.

필수 시작 상태
- Shopling [A18] 쇼핑몰상품등록 탭 1개를 정상 로그인 상태로 열어둡니다.
- 이 A18 탭은 컨트롤/원본 템플릿이며 자동화가 검색/선택/송신에 사용하지 않습니다.
- 기존 운영용 Commerce OS Shopling Bridge는 OFF로 둡니다.
- 탭 순서, 활성 탭, 다른 작업 여부, Windows 가상 데스크톱 위치는 중요하지 않습니다.
- 기존 shopling.co.kr 메인 탭이나 login_proc.php 탭은 v0.3.3 자동화에 필요하지 않습니다.

v0.3.3 A18 복제 안전계약
1. 사용자가 버튼을 누른 현재 A18 탭 ID를 원본 컨트롤 탭으로 고정합니다.
2. 각 채널 시작마다 chrome.tabs.duplicate()로 그 원본 A18 탭만 복제합니다.
3. 복제 탭을 별도 Chrome 작업창으로 옮긴 뒤 새로고침하여 깨끗한 A18 상태를 준비합니다.
4. 원본 A18 탭은 절대 닫거나 이동하거나 검색/체크하지 않습니다.
5. 복제 작업창 준비가 실패하면 Shopling 송신 단계로 가지 않고 해당 run의 송신 전 claim을 queued로 원복합니다.
6. 채널 성공 후에는 복제 작업창과 그 하위 팝업/결과창만 폐기합니다.
7. 다음 채널은 다시 같은 원본 A18 탭을 새로 복제해서 시작합니다.

채널 순환
1. 복제 A18 작업창에서 현재 채널의 자사상품코드로 미등록 검색합니다.
2. 같은 행의 Shopling goods_key(상품번호) + 자사상품코드가 모두 정확히 일치해야 선택합니다.
3. 해당 도매/소매 저장검색을 ID 선택 화면과 연동정보 화면에 각각 적용합니다.
4. 상품등록송신 직전에 Commerce OS durable submit lock을 획득합니다.
5. 실제 /prod_a/prod_rgst_rspt.phtml 결과 페이지가 처리완료되고 성공건수>0, 실패건수=0일 때만 sent 기록합니다.
6. 성공하면 해당 복제 작업창만 닫고 원본 A18을 다시 복제해 다음 채널로 진행합니다.
7. 송신 전 실패는 현재/미시작 채널을 queued로 원복합니다.
8. 송신 경계 이후 결과가 불명확하면 confirm_needed로 멈추며 자동 재송신하지 않습니다.

운영 주의
- 원본 A18 탭과 Chrome 자체만 닫지 않습니다.
- 다른 탭에서 업무를 하거나 가상 데스크톱을 이동해도 됩니다.
- 원본 A18 탭을 다른 메뉴로 이동시키면 다음 복제 전에 안전중단할 수 있습니다.
- 확인필요가 뜨면 다시 버튼을 누르지 않습니다.
